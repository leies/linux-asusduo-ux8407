1. Hardware we were dealing with

This laptop is not a generic Intel notebook. It is a 2026 dual-OLED convertible with a detachable USB keyboard. Almost every bug came from that combination plus Intel’s new xe GPU driver and SoundWire audio.

PieceWhat it is
DMIZenbook Duo UX8407AA, BIOS UX8407AA.308
CPU / GPUIntel Core Ultra X7 358H, Arc B390, driver xe
PanelsTwo BOE 2880×1800@144Hz OLEDs: eDP-1 (top), eDP-2 (bottom, PHY B / pipe B)
KeyboardPrimax USB 0b05:1cd7, bound to hid-generic (not hid-asus)
AudioSOF Panther Lake + CS42L43 (headset) + 2× CS35L56 (speakers) + a ghost RT722 in ACPI

2. The three original problems

  1. Boot freeze. Wallpaper and cursor appeared, then the session hung ~70s. Kernel: PSR / Panel Replay, then eDP-2 link-training failure on PHY B, stacked flip_done timed out.
  2. No brightness. intel_backlight sysfs writes succeeded; the OLEDs ignored PWM. Classic Panther Lake DPCD-AUX mismatch. Omarchy already had this fix for UX5406AA / B9406, not UX8407.
  3. Fn keys wrong, then no speakers. F-row arrived as F1–F12. Later, PipeWire only had Dummy Output because sof_sdw died creating two SDW3-Playback-SimpleJack DAIs.

3. Changes, step by step

Failed attempts are included on purpose. They are the interesting part: each one taught why the next approach was required.

Step 1 — Diagnose the freeze and brightness KEPT

Journal showed Intel xe PSR idle timeouts and pipe-B flip_done waits of 10s each. Backlight nodes: intel_backlight (eDP-1), card0-eDP-2-backlight, and a broken asus_screenpad (max 255, current 130816). Omarchy brightness UI correctly prefers intel_backlight, but the panel wanted DPCD, not PWM. 

xe.enable_dpcd_backlight=1
xe.enable_psr=0
xe.enable_psr2_sel_fetch=0
xe.enable_panel_replay=0

Written to configs/etc/limine-entry-tool.d/asus-ux8407-display.conf, then limine-update.

Step 2 — Dual-panel brightness sync KEPT (harmless)

Omarchy only writes the top backlight. A user service watched intel_backlight and copied the percentage to eDP-2. After Phase 1 decided the bottom panel stays off forever, this service is unused at runtime but the idea still matters if you ever re-enable eDP-2.

Step 3 — Keyboard F-row and HID Fn-lock KEPT

USB ID 0b05:1cd7 is not in hid-asus, so Linux used hid-generic. Vendor page 0xFF31 (report 0x5A) was ignored. We did three layers:

  1. Hyprland binds in configs/hypr/bindings.lua (works even if firmware stays in F-key mode).
  2. udev hwdb remap of USB HID F1–F6 scancodes 7003a…7003f to mute/volume/kbdillum/brightness.
  3. Userspace HID feature reports on hidraw (report 0x5A): ASUS handshake "ASUS Tech.Inc.", Fn-lock ON 5a d0 4e 01, backlight 5a ba c5 c4 <0–3>.

hidraw is root-only by default. udev rule grants GROUP=input MODE=0660. A copy of the helper lives in /usr/local/bin because udev at boot cannot see an encrypted home.

F9 was voxtype push-to-talk; it was unbound. Dictation remains Super+Ctrl+X.

Step 4 — PSR gone, freeze still there FAILED as complete fix

After reboot, cmdline had the PSR flags. PSR idle errors disappeared. The hang moved to PHY B / eDP-2 link training: 

Failed to bring PHY B to idle
Timeout waiting for DDI BUF B to get active
[CONNECTOR:eDP-2] Failed to enable link training
[CRTC:pipe B] flip_done timed out
DSB 0 timed out waiting for idle

Hyprland’s first commit applied preferred 144Hz + transform = 2 (180°) to both OLEDs. That modeset is what wedged pipe B. There was also a Raydium touchscreen oops in the same window; it was not the main freeze.

Step 5 — Keep the bottom OLED off KEPT

Two layers, both required:

  1. Hyprland: explicit eDP-1 at 2880×1800@144, scale 1.6, transform 2; eDP-2 disabled = true.
  2. Kernel: video=eDP-2:d so KMS never trains PHY B at boot.

Also added xe.enable_dsb=0 for the remaining DSB timeouts.

A dock-watcher that would turn eDP-2 on when the keyboard was undocked was written, then disabled after you said the bottom screen must never come on. F7 (toggle bottom) was removed from the key map.

Step 6 — Audio: Dummy Output SEVERAL FAILURES, THEN SUCCESS

SOF firmware booted (v2.14.1.1). Codecs enumerated. Then: 

sysfs: cannot create duplicate filename
  '.../sof_sdw/SDW3-Playback-SimpleJack'
sof_sdw: probe failed with error -12

ACPI lists a Realtek RT722 on SoundWire link 3 next to the real CS42L43. Function topologies create a SimpleJack DAI for each. That is a known “ghost RT722” pattern on ASUS Panther Lake (UX5406AA). Upstream fix is a DMI _ADR remap in drivers/soundwire/dmi-quirks.c. Stock 7.1.8 does not match UX8407AA.

Attempts, in order:

AttemptResult
Blacklist snd_soc_rt722_sdca + force topology sof-ptl-cs42l43-agg-l3-cs35l56-l2.tplg FAIL sof_sdw never bound — it waits for every ACPI SDW device to have a driver.
Load RT722 again, keep forced topology FAIL Duplicate SimpleJack still created in mc_probe. The duplicate is from DAI-link construction, not from function-topology vs static tplg.
SSDT _STA=0 on SWD0 via mkinitcpio add_file FAIL File landed in the compressed initramfs. ACPI table upgrade runs before that unpacks. SWD0 still present; no UX8407 / NOSWD0 table in dmesg.
Embed SSDT in UKI .acpi via ukify config ACPI= FAIL systemd 261 ukify has no --acpi-table. Key ignored.
Wrap ukify in /usr/local/bin FAIL sudo secure_path skips /usr/local/bin, so mkinitcpio never saw the wrapper.
objcopy --add-section .acpi= onto the UKI DANGEROUS Section appeared at index 0 with bogus VMA 0x200000000 and shifted .text. Would likely brick boot. Reverted with a clean limine-update.
mkinitcpio add_file_early → uncompressed early cpio /kernel/firmware/acpi/*.aml SUCCESS This is what CONFIG_ACPI_TABLE_UPGRADE actually reads. After reboot, sof-soundwire registered; speakers worked.

The SSDT (also in acpi/ssdt-noswd0.asl):

DefinitionBlock ("", "SSDT", 2, "UX8407", "NOSWD0", 0x00000001)
{
    External (_SB_.PC00.HDAS.IDA_.SNDW.SWD0, DeviceObj)
    Scope (_SB.PC00.HDAS.IDA.SNDW.SWD0)
    {
        Method (_STA, 0, NotSerialized)
        {
            Return (Zero)
        }
    }
}

SWD0 is the ghost: ACPI _ADR = 0x000330025d072201 (link 3, vendor 0x025d product 0x0722). Real devices: SWD2/SWD3 = CS35L56 on link 2, SWD6 = CS42L43 on link 3. Speaker tuning blobs for PCI SSID 1043:1444 were already in linux-firmware-cirrus.

Step 7 — Mic mute on F10 KEPT

Default Omarchy bind is XF86AudioMicMute → omarchy-audio-input-mute. Phase 1 user map originally used F11. You asked for F10. F11 was cleared; F10 now toggles mute.

6. How to re-apply after an Omarchy / kernel update

  1. Copy the configs/etc/* tree back under /etc (needs root).
  2. Copy acpi/ssdt-noswd0.aml to /boot/acpi/.
  3. Confirm HOOKS+=(acpi_override) still runs after Omarchy’s mkinitcpio drop-in (filename zz-ux8407-acpi.conf is intentional).
  4. Run systemd-hwdb update && udevadm trigger and limine-update.
  5. Restore Hyprland files under ~/.config/hypr/.
  6. Copy the keyboard helper to both ~/.local/bin and /usr/local/bin.
  7. Reboot. Check: 
    cat /proc/asound/cards          # expect sofsoundwire
cat /proc/cmdline               # expect video=eDP-2:d and xe.enable_*
hyprctl monitors                # expect eDP-1 only
journalctl -b -k | grep NOSWD0  # ACPI overlay loaded

Do not re-enable eDP-2, do not put the SSDT only in the compressed initramfs, and do not objcopy a .acpi section onto the UKI with a bogus VMA — those three are the landmines from this phase.
